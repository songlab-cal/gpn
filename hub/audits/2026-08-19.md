# Hugging Face compatibility audit — 2026-08-19

## Outcome

All five supported model repositories and both required data-artifact repositories
were reachable at their immutable approved revisions. Their default branches still
resolved to those revisions, every required file was present, all five checkpoints
provided safetensors, and the declared architectures/model types matched the
installed-package registrations. The machine-readable result is
[`2026-08-19.json`](2026-08-19.json).

The public inventory covered 28 related models, 40 related datasets, five collections,
and two external collection references. This broad inventory is for discoverability
and documentation triage; only the five entries under `supported_models` in
[`../manifest.json`](../manifest.json) are package compatibility commitments.

## Method and safety boundary

`hub/audit_hub.py` queried the public Hugging Face API and read only small model
cards and configuration files. It downloaded no weights, dataset rows, or MSAs.
The public `multiz100way-pigz` archive was checked by metadata only because its
recorded size is 42,269,901,437 bytes.

The numerical part of the audit was performed separately with the opt-in published
model suite on Python 3.13.2, PyTorch 2.13.0 CPU, Transformers 5.15.0, NumPy 2.5.2,
and float32. GPN, GPN-MSA, GPN-Star, PhyloGPN, and Sorghum expression all reproduced
the approved notebook-derived outputs in
`tests/fixtures/published_model_baseline.json`. GPN-MSA and GPN-Star used only the
checked-in 128 bp NumPy fixture; no full alignment was downloaded.

## Compatibility findings

- GPN's config retains an inert absolute `_name_or_path` from its training system.
- GPN-MSA's config retains an opaque historical checkpoint path.
- GPN-Star's config retains a nonportable training-time `phylo_dist_path`. The
  maintained loader successfully uses the two bundled `phylo_dist/*.npy` files as
  its portable fallback.
- PhyloGPN still carries an `auto_map` and copied remote-code files. The supported
  path is the installed `gpn` package, explicit `register_auto_classes("phylo")`,
  and standard AutoClasses without `trust_remote_code`.
- Sorghum exposes generic `LABEL_0` through `LABEL_25`; its nonnegative outputs are
  predictions on the `log(1 + TPM)` scale, and the tested biological label order
  lives in the pinned `songlab/gxa-sorghum-v1/labels.txt` artifact.
- GPN and GPN-MSA provide both legacy PyTorch binaries and safetensors. This audit
  requires safetensors but does not delete remote files.

## Documentation findings

Every supported model card needs an update:

- GPN and GPN-MSA still show the removed implicit `import gpn.model` registration
  pattern.
- GPN-MSA's `fill-mask` and Sorghum's `text-classification` pipeline metadata expose
  generated interfaces that do not represent their required custom inputs/outputs.
- the audited GPN-Star card is a 24-byte license-only stub and lacks library
  metadata; its custom MSA inputs intentionally have no generic pipeline tag;
- PhyloGPN presents mutable remote code as the primary path and uses the ambiguous
  license identifier `cc`; and
- the Sorghum card is an unfilled generated template, lacks a license, and contains
  an unrelated carbon-emissions-paper reference.

The broader inventory also found a broken repository name in the
`multiz100way-pigz` download instructions and missing or stub cards for the
GPN-Star alignment datasets. Exact local proposals are kept under
`hub/card-proposals/`; none has been applied externally.

## Maintainer decisions before Hub writes

Do not guess the following facts:

- the precise PhyloGPN license;
- the Sorghum model/dataset license, assembly, RNA-seq accessions, and split
  procedure;
- the exact public archive/species-order mapping for the GPN-Star M447 checkpoint;
  and

These are documentation or asset-maintenance questions, not blockers for the five
tested installed-package inference paths.
